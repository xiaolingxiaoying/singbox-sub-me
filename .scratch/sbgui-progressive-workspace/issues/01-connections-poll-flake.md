# 连接页偶发 0 行，而同一时刻 clash_api 有 3 条活连接

Status: needs-triage
Type: task

## 现象

`scripts/sbgui-shot/` 用完全相同的脚本、相同的种子、相同的镜像跑两次：捕获瞬间 harness 打印的 `api rows:` 都是 `3 [('127.0.0.1','8099'), ('127.0.0.1','8099'), ('127.0.0.1','8098')]`，内核日志也确实记录了这三条 `outbound/direct` 连接。但一次截图渲染出 3 行表格，下一次渲染出"暂无活动连接"，侧边栏徽标同步显示 0。

两次运行内核状态都是"运行中"，页头 `0 条活动连接 · 代理 0 · 直连 0`。

## 证据

- 有行：`.scratch/sbgui-conn-live/1440x900-connections.png`
- 无行：`.scratch/sbgui-conn-fixed/1440x900-connections.png`
- 行数由 `scripts/sbgui-shot/inside.sh` 在 `import` 之前打印，读的是运行配置里的随机 controller 端点与密钥。

## 影响

这不是夹具问题，是刷新路径问题：连接列表只能通过引擎的周期快照到达界面，所以漏一次轮询不会报错，只会静默显示空态。用户在内核确实在跑的时候打开连接页，可能看到"暂无活动连接"。同类路径也喂给日志页和概览页的流量数字，需要一并查。

## 下一步

1. 读 `crates/client-core` 的引擎循环：连接列表的轮询周期、是否只在当前页可见时刷新、快照失败时是否保留旧值还是清空。
2. 读 `crates/sbgui/src/app.rs` 进入连接页时的首次刷新时机。
3. 先用一个能在容器里稳定复现 3 行的用例固定下来，再改。当前 harness 已经能打印行数，复现成本是一次约两分钟的捕获。
