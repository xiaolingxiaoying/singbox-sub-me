# 窄屏断点 820/560 在真实窗口里进不去

Status: needs-triage
Type: task

## 现象

原型的布局规范给了 820 与 560 两档断点，但 sbgui 设置了 `window_min_size`（`crates/sbgui/src/main.rs`，860×640），窗口拖不到那么窄，两档断点在任何真实使用里都是死代码。

## 影响

`acceptance.md` 第 4 条（390×844 无横向溢出）无法验证。当前所有截图都是 1440×900；860×640 的下限截图在 `.scratch/sbgui-min/`，那是能到达的最窄状态，仍宽于第一档断点。

## 需要决策

不是直接改小数字就行：更小的下限意味着侧栏、指标带和六列表格要在窄宽度下重排，而 GPUI 没有 CSS 那样的媒体查询，断点得自己按宽度分支。三个选项——

1. 保持 860×640，正式放弃窄屏，把 kit 的第 4 条标为不适用；
2. 下调到 560 一档，接受概览页在窄窗下的信息密度下降；
3. 下调但给侧栏加折叠，工作量最大。
