# sbgui — 桌面 sing-box 客户端

`sbgui` 是基于 GPUI 的桌面客户端（Windows，以及启用了 X11 后端的 Linux），与终端客户端
`sbtui` 共用同一个控制面（`crates/client-core`）。窗口本身只做两件事：渲染引擎发布的
`ClientSnapshot`，以及把用户操作转换成 `ClientCommand`。因此两个客户端在订阅、节点、
系统代理、TUN、流量、连接与日志上共享业务逻辑；桌面和终端的布局、操作入口与快捷键分别实现。

## 构建与运行

```bash
cargo build --release -p sbgui
# Windows 产出 target/release/sbgui.exe
# Linux 产出 target/release/sbgui
```

Windows / macOS 的 GPUI 后端无需额外系统库。Linux 上 `crates/sbgui/Cargo.toml` 会为
`cfg(target_os = "linux")` 启用 GPUI 的 `x11` 后端；缺少它时 GPUI 会静默退化为无窗口的
headless 渲染器。构建需要 X11 开发库：

```bash
sudo apt-get install -y --no-install-recommends \
  libfontconfig1-dev libfreetype6-dev libx11-dev libxcb1-dev \
  libxkbcommon-dev libxkbcommon-x11-dev libgl1-mesa-dev libegl1-mesa-dev \
  libvulkan-dev libasound2-dev
```

首次运行会在 `%APPDATA%\sbgui` 下创建 `settings.toml`、`profiles.toml`、`cache/` 与
`core/`。数据目录与 `sbtui` 分开，两个客户端因此各自持有订阅缓存与内核控制通道（端口和
认证秘密每次启动随机生成，互不可见）。注意 mixed 端口与系统代理是整机共享资源：两个客户端
同时运行时要把其中一方的 mixed 端口改开，否则后启动的内核会因端口被占而失败。

每个客户端都按数据目录取单实例锁（`client.lock`，由系统在进程结束时释放），重复启动的
第二个实例直接退出。退出时客户端会先停止内核再关窗（Windows 上另有 job object 兜底），
所以 sing-box 不会作为孤儿进程残留；若上次是非正常结束（崩溃、任务管理器结束）而留下了
系统代理设置，下次启动会自动把它恢复原状。

## 页面

| 页面 | 内容 |
| --- | --- |
| 概览 | 连接状态卡（首次使用时在同一卡内给出四步引导）、真实上下行流量折线与累计/峰值、内核内存与运行版本、活跃连接数 |
| 订阅 | 手动输入或从剪贴板导入订阅地址、切换当前档案、查看用量、立即更新与删除本地档案 |
| 节点 | 代理组切换（芯片带成员数）、可换行节点网格、当前节点标记、单节点及整组测延迟；自动组禁止手动切换，测试按钮不触发切换，超时显示为「超时」 |
| 规则 | 只读展示当前配置的路由规则（匹配条件与出站目标）和规则集来源（tag、类型、URL）；超过 120 条折叠 |
| 连接 | 关键字实时筛选（主机 / 目标 / 规则），可横向滚动的应用、目标、协议、命中规则、累计流量、建立时间表格（按下载量排序），点击行展开详情，断开单条或全部连接；超过 120 条折叠 |
| 日志 | sing-box 内核日志与运行事件流，支持级别筛选（全部 / info+ / warn+ / error）与关键字过滤 |
| 设置 | 订阅档案激活、内核版本与下载、可编辑的固定版本 / 镜像 / 混合端口 / 延迟地址 / 自动更新间隔（回车保存，Esc 还原）、流量模式、自动化开关 |

## 控制面

`sbgui` 通过 `client_core::ClientController` 驱动引擎：

- `controller.snapshot()`：非阻塞地读取最新 `ClientSnapshot`，窗口每 400ms 轮询一次。
- `controller.send(cmd)`：非阻塞地提交命令（启动/停止内核、切换节点、测延迟、系统代理、
  TUN、订阅更新、内核下载、设置修改、关闭连接等）。
- 引擎在后台以 500ms 的节拍轮询流量、内存、连接与代理组，维护速率历史，解析并发布
  当前配置的路由规则，记录运行中内核版本，并在内核意外退出时按指数退避自动重启。

引擎内部依赖 `tokio`，由 `main` 创建一个多线程 runtime 承载；GPUI 只负责界面线程。

## 界面与操作

界面学习 [Clash Party 的操作组织](https://clashparty.org/docs/handson)，保留 GPUI 原生实现与共享控制面，不引入上游源码。

- 216px 导航侧栏只放七个页面的纵向导航，底部保留一行实时上下行摘要；出站模式、系统代理、TUN 与内核状态不再在侧栏重复。
- TUN 在内核运行或启动期间不可切换，界面提示「停核后切换」；该开关表达所选配置，不能据此推断流量已经由 TUN 接管。
- 页面只有两条固定横带：46px 自绘标题栏，和把页面名、引擎状态行与内核/出站模式/当前节点/系统代理/TUN 状态胶囊合并成的一行工具条（窄窗口自动换行）。启动可直接执行，停止与重启收进 `···`。
- 排版使用一套阶梯：20/14/13/12/11px 五档字号，区块间距 20px，卡片内边距 20px，列表行上下 13px、左右 20px，最小字号不低于 11px。
- 订阅档案为两行式列表行，节点行为单行，规则与连接表去掉恒定的状态列；日志去掉序号列与重复的面板标题，视图控制并入列表容器自己的头部。选中项用淡色整行加「当前」文字表达，用户无需退出 GUI 编辑 `profiles.toml` 即可导入或删除订阅。
- 规则与连接列表默认只画前 120 行，底部按需展开；空列表在容器内使用无框提示，容器无内容时不绘制表头。
- 文本输入为最小实现：点击聚焦、行尾追加/退格、Enter 提交、Esc 还原；IME（中文）输入暂不支持，筛选与设置项为 ASCII 场景。
- 关闭窗口（按钮或 Alt+F4）时若系统代理仍开启，会弹出退出确认：恢复代理设置后退出、保留设置退出或取消。
- Windows 系统标题栏隐藏为透明非客户区；品牌、拖拽区域、最小化、最大化和关闭按钮全部由 GPUI 绘制，窗口缩放边缘仍由 GPUI/Win32 命中测试保留。Windows 11 使用系统 DWM 圆角，内容层同步裁切为 16px 圆角。
- 标题栏左上角绘制 `assets/serein.ico`（经 `AssetSource` 内嵌，GPUI 用 `image` 的 ICO 解码器渲染），同一文件也由 `build.rs` 写入可执行文件图标；流量趋势使用 GPUI canvas 绘制真实历史采样。默认窗口为 1080×760px，最小窗口为 860×640px；侧栏和内容可滚动，连接表支持横向滚动。

视觉规则见根目录 `DESIGN.md`。终端客户端的快捷键帮助与确认浮层不能视为 GUI 已实现功能。
本说明依据当前源码；旧 `.impeccable/mocks` 图片不是当前运行截图。当前布局已用原生窗口截图复核
（概览、订阅、节点、规则、连接、日志、设置与退出浮层）；节点、规则、连接三页带真实内核数据的
密集行仍需在有内核的环境里复核——本机 `%APPDATA%\sbgui` 的 `core/` 为空，无法在不触碰系统代理
的前提下取到这些数据。
