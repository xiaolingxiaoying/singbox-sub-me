# 客户端功能与作用说明

## 1. 客户端定位

本项目包含两类客户端：

- `sbtui`：终端/TUI 客户端；
- `sbgui`：桌面/GUI 客户端；
- `client-core`：两个客户端共用的核心控制层。

客户端的核心作用是：

> 将服务端提供的 sing-box 订阅导入本机，运行本地 sing-box 内核，并提供节点切换、系统代理、TUN、流量、连接和日志管理能力。

客户端不是简单的订阅查看器，而是一个完整的本地 sing-box 代理管理器。

服务端 `sbctl` 负责部署 sing-box、生成订阅和维护 VPS；客户端则负责在用户电脑上消费订阅并接管本机网络流量。

## 2. 整体工作流程

```text
导入订阅
   ↓
解析并归一化订阅地址
   ↓
下载 sing-box 配置
   ↓
根据本地模式适配入站配置
   ↓
启动本机 sing-box 内核
   ↓
通过 Clash API 控制代理组和节点
   ↓
启用系统代理或 TUN 模式
   ↓
查看流量、连接、延迟和日志
```

## 3. 客户端架构

```text
sbtui / sbgui
        ↓
    client-core
        ↓
本机 sing-box + Clash API + 操作系统网络代理
```

### 3.1 `client-core`

`client-core` 是两个界面共用的业务控制层，负责：

- 订阅导入、解析和更新；
- sing-box 内核下载、启动、停止和重启；
- sing-box 配置适配；
- Clash API 通信；
- 节点切换和延迟测试；
- 系统代理开关；
- TUN 模式管理；
- 流量统计；
- 内核内存占用与运行版本读取；
- 路由规则与规则集解析并发布给界面；
- 活跃连接管理；
- 日志收集；
- 设置和订阅档案持久化；
- sing-box 异常退出后的自动重启。

界面只负责渲染 `ClientSnapshot`，并通过 `ClientCommand` 向控制层发送操作命令。这样可以保证终端客户端和桌面客户端使用相同的业务逻辑。

### 3.2 `sbtui`

`sbtui` 是运行在终端中的客户端，适合：

- SSH 环境；
- Linux/macOS 终端；
- Windows Terminal；
- 偏好键盘操作的用户。

它提供全键盘交互、概览、节点、连接、日志和设置页面。`sbtui` 自身不包含内核管理或轮询代码：它是共享控制层之上的纯渲染层，与 `sbgui` 走同一条引擎路径（包括启动时按设置自动拉起内核）。

### 3.3 `sbgui`

`sbgui` 是桌面图形客户端，主要面向 Windows，提供：

- 图形化订阅管理；
- 节点网格；
- 流量图表；
- 连接表格；
- 日志窗口；
- 设置页面；
- sing-box 启动和停止控制。

## 4. 订阅管理

### 4.1 支持的订阅来源

客户端支持导入：

- `sbctl` 生成的 `sing-box-full.json`；
- `sing-box.json`；
- 明文 URI 列表；
- Base64 URI 列表；
- 二维码地址或订阅总览页地址；
- 本地订阅文件。

注意：客户端不解析 Clash/Mihomo YAML 的配置内容。`sbctl` 的 `clash.yaml` 订阅链接会通过地址归一化转换为 `sing-box-full.json`；来自第三方的 Clash YAML 订阅不受支持。

### 4.2 订阅地址归一化

对于 `sbctl` 生成的不同订阅后缀，客户端会自动转换为完整的 sing-box 客户端配置。

例如以下地址最终都会归一化为同一个完整配置地址：

```text
/sub/<凭据>/index
/sub/<凭据>/qr/sing-box-full
/sub/<凭据>/clash.yaml
/sub/<凭据>/sing-box.json
```

归一化后的目标地址为：

```text
/sub/<凭据>/sing-box-full.json
```

这样可以避免用户手动选择订阅格式，也能保证客户端拿到包含入站、路由、代理组和 Clash API 的完整配置。

### 4.3 订阅档案

客户端支持保存多个订阅档案。每个档案包含：

- 档案名称；
- 订阅地址；
- 原始地址；
- 最近成功更新时间；
- 是否为当前激活档案；
- 对应的本地缓存配置。

用户可以保存家庭节点、工作节点、备用节点等多个订阅，并在客户端中快速切换。

### 4.4 订阅更新

支持：

- 手动更新；
- 按分钟自动更新；
- 更新失败时继续使用上一次成功的缓存配置；
- 对旧版 `sbctl` 订阅接口进行兼容回退。

当完整客户端配置接口不可用，但原始链接是旧版 `sing-box.json` 时，客户端可以回退到基础节点配置，并在本地补齐必要的入站、选择器和 Clash API 配置。

## 5. sing-box 内核管理

客户端本身不是代理数据面，真正处理网络流量的是 sing-box。客户端负责管理 sing-box 的完整生命周期。

### 5.1 下载和安装内核

客户端可以根据当前平台和架构下载 sing-box：

- Windows；
- Linux；
- macOS；
- AMD64；
- ARM64。

Windows 下还会处理 `wintun.dll`，因为 TUN 模式需要该组件。

### 5.2 版本管理

用户可以：

- 使用最新版本；
- 固定某个 sing-box 版本；
- 配置下载镜像；
- 重新下载内核；
- 查看当前内核版本；
- 查看运行中内核通过 Clash API 上报的版本（与安装的二进制版本分开显示）。

下载的内核归档会计算 SHA-256 并按版本号记录在本地（`core/verified-hashes.json`）。sing-box 官方不发布校验文件，因此首次下载无法远程比对；但同一版本再次下载（例如更换镜像后）若哈希与首次记录不一致，客户端会拒绝安装并提示可能的篡改。

### 5.3 启动前配置检查

启动内核前，客户端会先调用 sing-box 的配置检查能力，确认本地运行配置有效后才启动内核。

### 5.4 异常自动重启

如果 sing-box 意外退出，客户端会：

1. 检测到内核退出；
2. 记录错误信息；
3. 按指数退避等待；
4. 自动重新启动内核。

重启等待时间会逐步增加，例如：

```text
2 秒 → 4 秒 → 8 秒 → 16 秒 → 30 秒
```

## 6. 系统代理

客户端可以将操作系统代理指向本地 sing-box。

默认本地混合代理端口通常为：

```text
127.0.0.1:2080
```

启用系统代理后，支持系统代理设置的浏览器、开发工具和桌面应用可以通过本地 sing-box 转发。

客户端在修改系统代理前会保存原来的代理设置，关闭代理时尝试恢复原配置。

支持的平台包括：

- Windows；
- macOS；
- Linux。

## 7. TUN 模式

TUN 模式通过创建虚拟网卡接管更多系统流量，适合不支持手动配置代理的软件。

客户端生成的 TUN 入站通常包括：

- 自动路由；
- 严格路由；
- IPv4；
- IPv6；
- mixed 网络栈；
- 自动探测出口网卡。

系统代理和 TUN 的区别如下：

| 模式 | 工作方式 | 适合场景 |
| --- | --- | --- |
| 系统代理 | 应用主动连接本地代理 | 浏览器、开发工具、普通桌面软件 |
| TUN | 系统流量进入虚拟网卡 | 不支持代理的软件、较完整的全局接管 |

TUN 模式有更高的权限要求：

- Windows 通常需要管理员权限；
- Linux/macOS 需要 root 或相应网络权限；
- Windows 需要 `wintun.dll`；
- 切换模式后通常需要重启 sing-box；
- 内核运行期间不能直接修改流量模式。

## 8. 节点和代理组管理

客户端通过 sing-box 配置中的 Clash API 控制节点。

服务端生成的完整配置通常包含：

- 节点选择组；
- 自动测速组；
- 直连组；
- VLESS Reality 节点；
- VMess WebSocket 节点；
- Hysteria 2 节点；
- TUIC 节点；
- AnyTLS 节点。

客户端可以显示：

- 代理组名称；
- 当前节点；
- 组内节点列表；
- 节点延迟；
- 超时或失败节点；
- 自动选择组状态。

### 8.1 手动切换节点

对于手动选择组，用户可以直接选择节点。客户端会通过 Clash API 通知 sing-box 切换当前代理节点，并刷新界面状态。

### 8.2 自动选择组

自动测速组由 sing-box 根据延迟测试结果自动选择节点。客户端可以测试这些节点，但不会强制用户手动修改自动组的当前节点。

### 8.3 延迟测试

支持：

- 测试单个节点；
- 并发测试整个代理组；
- 自定义测试地址；
- 显示毫秒延迟；
- 显示超时和失败节点。

节点列表在手动测试之前就会显示 sing-box 内核最近上报的延迟（来自 Clash API 的节点历史）；客户端自己实测的结果会覆盖内核上报值，超时的节点显示为「超时」。

## 9. 出站模式

客户端支持在以下三种模式之间切换：

```text
规则模式 → 全局模式 → 直连模式
```

### 规则模式

根据 sing-box 配置中的路由规则分流，例如：

- 国内网站直连；
- AI 服务走代理；
- 私有地址直连；
- 其他流量按规则处理。

### 全局模式

尽量让所有流量经过当前代理节点。

### 直连模式

不经过代理，直接连接目标地址。

这个功能控制的是 sing-box 的出站模式，不是切换订阅档案。

## 10. 流量统计

客户端通过 Clash API 持续读取 sing-box 的本机运行数据，可以显示：

- 实时上传速度；
- 实时下载速度；
- 累计上传量；
- 累计下载量；
- 最近一段时间的速度变化；
- 速度峰值；
- 内核进程的内存占用（Clash API `/memory`）；
- 运行中内核的版本（Clash API `/version`）。

客户端会保留约 5 分钟的历史采样，用于绘制速度曲线：

- `sbtui` 使用终端字符图或 sparkline；
- `sbgui` 使用桌面图形曲线。

需要注意：客户端显示的是本机 sing-box 的流量，不是服务端 VPS 的总流量。服务端订阅中的 `subscription-userinfo` 主要反映 VPS 网卡流量。

## 11. 连接管理

客户端可以查看 sing-box 当前的活跃连接，包括：

- 目标地址；
- 目标主机；
- 目标 IP 和端口；
- 网络类型；
- 命中的分流规则；
- 出站链路；
- 上传流量；
- 下载流量。

支持的操作包括：

- 按关键字过滤；
- 按下载量排序；
- 按上传量排序；
- 按主机排序；
- 按目标排序；
- 关闭单条连接；
- 关闭全部连接。

这些功能主要用于排查：

- 某个程序是否经过代理；
- 某个域名被分流到哪里；
- 某条连接是否持续占用带宽；
- 当前路由规则是否按预期命中。

## 12. 日志和诊断

客户端提供两类日志。

### 12.1 sing-box 内核日志

客户端实时读取本地缓存的内核日志，例如：

```text
cache/core.log
```

支持：

- 实时跟随日志；
- 暂停或恢复滚动；
- 按 `info`、`warn`、`error` 等级别过滤；
- 按关键字搜索。

### 12.2 客户端运行事件

客户端会记录自身状态变化，例如：

- 订阅更新成功或失败；
- 内核启动或停止；
- 内核异常退出；
- 节点切换；
- 延迟测试结果；
- 系统代理启用或关闭；
- 自动重启事件。

这样可以区分 sing-box 内核错误和客户端控制流程错误。

## 13. 路由规则查看

两个客户端都能查看当前激活配置的路由规则，数据由 `client-core` 从
`cache/active-config.json` 解析后放进快照统一发布：

- 分流规则按自上而下的匹配顺序展示：匹配条件（域名后缀、域名、域名关键字、
  规则集、网段、私有地址、协议、网络、端口等）与目标出站；
- 非转发动作（如 `hijack-dns`）显示为规则的动作；
- 配置的 `final` 兜底出站单独显示为「其他未命中流量」；
- 远程/本地规则集（`route.rule_set`）显示 tag、类型与来源 URL。

`sbgui` 提供独立的「规则」页；`sbtui` 在「日志」页按 `r` 切换到分流规则视图。
规则数据在内核启动（重写激活配置）时刷新；客户端启动时也会读取上一次的激活
配置，因此内核停止后仍可查看上一次的规则。

## 14. `sbgui` 桌面客户端页面

| 页面 | 主要用途 |
| --- | --- |
| 概览 | 查看内核状态、当前节点、实时流量、内核内存与运行版本、连接数量 |
| 订阅 | 导入、激活、刷新和删除订阅 |
| 节点 | 切换代理组、选择节点和测试延迟 |
| 规则 | 查看当前配置的路由规则与规则集来源 |
| 连接 | 查看、筛选和关闭连接 |
| 日志 | 查看内核日志和客户端事件 |
| 设置 | 设置内核版本、代理端口、TUN、更新和自动化行为 |

桌面侧边栏还会显示：

- 规则/全局/直连模式；
- 系统代理状态；
- TUN 状态；
- 当前订阅；
- 订阅用量；
- 实时上下行速率；
- sing-box 内核运行状态。

## 15. `sbtui` 终端客户端操作

| 快捷键 | 作用 |
| --- | --- |
| `Tab` / `1`–`5` | 切换页面 |
| `s` | 启动或停止内核 |
| `p` | 开关系统代理 |
| `m` | 切换系统代理/TUN 模式 |
| `u` | 更新订阅 |
| `t` | 测试当前节点 |
| `T` | 测试整组节点 |
| `o` | 切换规则/全局/直连模式 |
| `x` | 关闭当前连接 |
| `X` | 关闭全部连接 |
| `S` | 切换连接表排序（下载/上传/主机/目标） |
| `/` | 搜索连接或日志 |
| `Space` / `l` / `c` | 日志页：暂停滚动 / 级别过滤 / 复制当前行 |
| `r` | 日志页切换到分流规则视图 |
| `n` / `f` / `e` / `Delete` | 设置页：新增 / 本地文件导入 / 改链接 / 删除档案 |
| `d` / `v` / `r` | 设置页：下载内核 / 固定版本 / 设置镜像 |
| `a` / `P` / `U` / `g` / `y` | 设置页：自动更新间隔 / 混合端口 / 延迟地址 / 自动启动 / 自动系统代理 |
| `?` | 查看帮助 |
| `q` | 退出客户端 |

当系统代理仍然开启时退出，客户端会询问是否保留系统代理，避免退出客户端后系统仍然指向已经停止的本地代理端口。

## 16. 本地数据目录

客户端在本地维护以下内容：

```text
settings.toml
profiles.toml
cache/
core/
```

Windows 默认目录类似：

```text
%APPDATA%\sbtui
%APPDATA%\sbgui
```

Linux/macOS 默认目录类似：

```text
~/.config/sbtui
~/.config/sbgui
```

其中：

- `settings.toml`：本地客户端设置；
- `profiles.toml`：订阅档案；
- `cache/`：订阅缓存和日志；
- `core/`：sing-box 内核及 Windows TUN 组件。

`sbtui` 和 `sbgui` 使用不同的数据目录，因此不会同时争抢同一个 sing-box 进程。

## 17. 客户端职责边界

客户端负责：

- 导入和更新订阅；
- 在本机运行 sing-box；
- 切换节点和代理组；
- 启用系统代理或 TUN；
- 查看本机流量和连接；
- 查看日志并进行故障排查。

客户端不负责：

- 部署 VPS；
- 生成服务端协议凭据；
- 管理 VPS 防火墙；
- 管理 Nginx 或 Caddy；
- 申请服务端 ACME 证书；
- 修改服务端 sing-box 配置；
- 管理服务端流量账期；
- 提供 Web 管理面板；
- 统计每个服务端协议节点的独立用量。

这些功能属于服务端 `sbctl` 控制面的职责。

## 18. 总结

本项目客户端可以概括为：

> 一个以 sing-box 为数据面、以 `client-core` 为控制面，同时提供终端和桌面界面的本地代理管理器。

它重点解决以下问题：

1. 如何导入并管理订阅；
2. 如何在本机运行 sing-box；
3. 如何切换和测试节点；
4. 如何让系统流量进入代理；
5. 如何查看实时流量和活跃连接；
6. 如何通过日志排查代理问题；
7. 如何让 sing-box 在异常退出后自动恢复。

整体定位接近 Clash Party、Clash Verge 一类客户端，但底层围绕项目自有的 `sbctl` 订阅格式和 sing-box 完整配置构建。
