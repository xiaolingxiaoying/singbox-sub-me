# Serein GUI 客户端 UI 审计与改版建议

> 文档状态：设计建议稿  
> 审计日期：2026-09-19  
> 审计范围：概览、订阅、节点、规则、连接、日志、设置及退出确认流程  
> 截图来源：`/.scratch/gui-screenshots/`

## 1. 改版目标

当前 GUI 已具备清晰的一级导航、完整的核心功能和相对统一的青绿色视觉语言，但整体仍偏向“卡片堆叠式管理后台”。本次改版建议将产品定位为一个专业、克制、高效的桌面网络控制台。

改版应优先达成以下目标：

1. 用户打开客户端后，能够立即确认内核、代理、TUN、出站模式和当前节点的状态。
2. 高频操作始终可见，低频操作不长期占用主界面空间。
3. 减少重复信息、无效留白和过量卡片，提高桌面窗口的信息密度。
4. 强化节点选择、连接查看、日志排查等专业工具场景的效率。
5. 保留现有青绿色品牌特征，同时建立统一的排版、颜色、间距和交互规范。

## 2. 当前界面的优势

- 概览、订阅、节点、规则、连接、日志、设置的一级结构明确。
- 页面标题和说明能帮助初次使用者理解页面用途。
- 当前导航项具有明确的选中状态。
- 青绿色品牌色辨识度较高，整体视觉噪声较少。
- 已覆盖未启动、运行中、退出确认等关键客户端状态。
- 规则页的信息组织相对成熟，已经具备较好的可读性。

## 3. 核心问题

### 3.1 全局状态过于分散

内核状态、系统代理、TUN、出站模式、当前节点分别出现在页面标题区、侧栏和概览卡片中。部分信息重复出现，但用户仍需要在多个区域之间寻找当前状态。

建议建立统一的全局状态控制条，集中展示并操作：

- 内核运行状态
- 当前出站模式
- 当前节点及延迟
- 系统代理状态
- TUN 状态

### 3.2 卡片过多，信息密度偏低

当前几乎每一项内容都使用独立圆角卡片承载。虽然界面看起来整洁，但也造成以下问题：

- 页面被大量边框和圆角切碎。
- 设置页阅读顺序不稳定。
- 宽屏和高窗口下出现大量无效空白。
- 高频状态和普通信息缺少明显的视觉层级差异。

### 3.3 危险操作权重过高

“停止内核”在多个页面右上角作为主按钮出现。该操作影响较大，却获得了与页面主要任务相同甚至更高的视觉权重。

建议将停止、重启内核收进全局状态区的二级菜单，仅在概览页或故障状态下直接展示必要操作。

### 3.4 页面标题区占用空间过多

面包屑、页面标题、说明文字、内核状态和操作按钮共同占用了较大的纵向空间。切换页面后，真正的功能内容经常从窗口较下方才开始。

建议将标题区压缩至约 `80–104px`，并移除每页重复的内核状态和按钮。

### 3.5 侧栏视觉负担较重

每个导航项都使用独立卡片边框；下方又放置出站模式、系统代理、TUN、订阅、实时流量和内核状态，使侧栏同时承担导航、状态和操作三种职责。

建议将侧栏缩减为单一连续导航列表，仅在底部保留紧凑的实时流量或连接状态摘要。

## 4. 建议的信息架构

```text
┌────────────────────────────────────────────────────────────┐
│ Serein   当前：已连接 · 香港 01          搜索  通知  设置   │
├──────────────┬─────────────────────────────────────────────┤
│ 概览         │ 全局控制条                                  │
│ 订阅         │ [内核运行] [规则模式] [系统代理] [TUN]      │
│ 节点         ├─────────────────────────────────────────────┤
│ 规则         │                                             │
│ 连接         │ 当前页面内容                                │
│ 日志         │                                             │
│              │                                             │
│ 设置         │                                             │
├──────────────┤                                             │
│ ↓ 856 KiB/s  │                                             │
│ ↑ 544 KiB/s  │                                             │
└──────────────┴─────────────────────────────────────────────┘
```

推荐尺寸：

- 应用标题栏：约 `52–56px`
- 左侧导航：约 `220–240px`
- 页面内容最大宽度：约 `1240–1320px`
- 页面左右边距：`24–32px`
- 页面标题区：约 `80–104px`
- 普通内容间距：`16–24px`

窗口较窄时，侧栏应支持折叠为图标模式；窗口较宽时，主内容不应无限拉伸，而应保持适合阅读的最大宽度。

## 5. 页面级改版建议

### 5.1 概览

参考截图：[`01-dashboard.png`](../.scratch/gui-screenshots/01-dashboard.png)、[`02-dashboard-tall.png`](../.scratch/gui-screenshots/02-dashboard-tall.png)

建议在页面顶部首先显示连接状态卡，内容包括：

- 已连接或未连接
- 当前订阅
- 当前节点及延迟
- 出站模式
- 系统代理和 TUN 状态

下载、上传、活跃连接和累计流量应改为四个等权指标。当前只有下载卡片使用大面积品牌色，会无意中暗示下载比其他状态更重要。

流量趋势图应成为概览页的主要数据区域，并提供 `5 分钟 / 1 小时 / 24 小时`时间范围。内存占用、内核版本和自动重启次数可合并为紧凑的“运行状态”区域，不需要各自占据大卡片。

未配置状态建议改为明确的步骤引导：

```text
添加订阅 → 选择节点 → 启动内核 → 开启系统代理
```

### 5.2 订阅

参考截图：[`03-subscriptions.png`](../.scratch/gui-screenshots/03-subscriptions.png)

“导入订阅地址”属于低频操作，不应长期占据页面顶部的大块空间。建议改为顶部工具栏：

- `+ 添加订阅`
- `从剪贴板导入`
- `全部更新`

点击添加后使用对话框或右侧抽屉完成导入。

订阅列表建议显示：

- 订阅名称
- 当前使用状态
- 已用流量和总流量
- 到期时间
- 上次更新时间
- 节点数量

更新、编辑和删除操作放置在行尾。删除应位于“更多”菜单中，避免误触。当前订阅除浅色背景外，还应使用勾选和“当前”文字共同表达状态。

### 5.3 节点

参考截图：[`04-proxies.png`](../.scratch/gui-screenshots/04-proxies.png)

节点页是客户端最重要的高频操作页之一，应优先提升操作效率。

顶部工具栏建议包括：

- 代理组切换
- 节点搜索
- 地区、协议和延迟筛选
- 全部测速
- 卡片或列表视图切换

节点项建议显示名称、地区、协议、延迟和最近测速时间。延迟必须显示具体数字，如 `86 ms`，颜色只作为辅助信息。

当前节点需要明确的勾选和“当前”标签。整行或整张卡片可点击切换，因此无需重复展示“点击切换”。现有 🚀 等 emoji 应替换为统一图标库中的图标。

节点数量较多时，默认使用紧凑列表视图；卡片视图可作为用户偏好选项。

### 5.4 规则

参考截图：[`05-rules.png`](../.scratch/gui-screenshots/05-rules.png)

规则页现有结构已经较为清楚。建议进一步统一为表格：

| 优先级 | 匹配条件 | 出站 | 状态 |
|---|---|---|---|
| 01 | 其他匹配条件 | sniff | 已启用 |

其他建议：

- 规则集区域支持折叠，默认只显示摘要。
- 增加规则搜索和按出站筛选。
- 支持展开查看完整匹配条件。
- 如果状态不可操作，使用状态点即可；如果允许切换，则使用开关。

### 5.5 连接

参考截图：[`06-connections.png`](../.scratch/gui-screenshots/06-connections.png)

建议将默认重点列调整为：

- 应用或进程
- 远程目标
- 协议
- 命中规则
- 使用节点
- 实时速率
- 持续时间

源 IP、完整建立时间等低频信息可以放入行详情。表头应固定，内容区域独立滚动；长文本省略时提供悬浮提示或详情展开。

建议增加：

- 暂停实时刷新
- 仅显示活动连接
- 按应用、节点或规则筛选
- 单条关闭连接
- 连接详情抽屉

“关闭全部”使用危险色描边，并在执行前二次确认。

### 5.6 日志

参考截图：[`07-logs.png`](../.scratch/gui-screenshots/07-logs.png)

日志页建议采用更接近开发工具的日志查看器设计：

- 日志正文使用等宽字体。
- 时间、级别和来源从正文中拆分出来，避免重复。
- 提供自动滚动、自动换行、复制、清空和导出。
- 级别筛选统一为 `全部 / Debug / Info / Warn / Error`。
- 支持点击一行展开原始日志。
- 错误和警告同时使用图标、文字和颜色标记。

`info+`、`warn+` 等筛选名称需要用户自行猜测含义，建议改为常见级别名称，或在界面中明确解释其过滤规则。

### 5.7 设置

参考截图：[`08-settings.png`](../.scratch/gui-screenshots/08-settings.png)

设置页是当前最需要重新排版的页面。双列卡片高度不一致，导致阅读顺序不稳定；“输入后按 Enter 保存”也缺乏明确反馈。

建议使用二级导航或顶部标签：

- 常规
- 网络与端口
- 内核
- TUN
- 自动化
- 外观
- 高级

每个分组使用单列设置行：

```text
设置名称                                      控件
一行简短说明
────────────────────────────────────────────────
```

保存机制应统一为以下二者之一：

1. 修改后自动保存，并立即显示成功或失败反馈。
2. 页面底部固定显示“保存更改”按钮。

不建议同时使用自动保存、Enter 保存和独立操作按钮。

如果修改内核、端口或 TUN 设置后需要重启，应显示明确的待应用状态，例如：

> 有 3 项更改需要重启内核后生效。

“切换流量模式”和“循环出站模式”应改为明确的下拉选项。高风险或低频设置移入“高级”，并提供恢复默认值。

### 5.8 退出确认

参考截图：[`09-exit-confirm.png`](../.scratch/gui-screenshots/09-exit-confirm.png)

建议文案调整为：

- 标题：`退出 Serein？`
- 提示：`退出会停止 sing-box。若保留系统代理，其他应用可能无法联网。`
- 主按钮：`关闭系统代理并退出`
- 次按钮：`仅退出`
- 取消按钮：`取消`

“仅退出”需要附带危险提示：`系统代理设置将保留`。按钮统一靠右排列，并默认聚焦最安全的操作。

## 6. 视觉规范建议

### 6.1 颜色

| 用途 | 建议色值 |
|---|---|
| 页面背景 | `#F7F8FA` |
| 卡片背景 | `#FFFFFF` |
| 主文字 | `#101828` |
| 次文字 | `#667085` |
| 边框 | `#E4E7EC` |
| 品牌色 | `#0F766E` |
| 成功 | `#15803D` |
| 警告 | `#B45309` |
| 危险 | `#DC2626` |

品牌色主要用于主操作、选中状态、关键指标和焦点状态，不建议用于大面积卡片填充。

### 6.2 字体与字号

Windows 客户端建议优先使用：

```text
Segoe UI Variable, Microsoft YaHei UI, Noto Sans SC, sans-serif
```

| 内容 | 建议字号 |
|---|---|
| 页面标题 | `28–32px` |
| 区块标题 | `18–20px` |
| 普通正文 | `14px` |
| 辅助信息 | `12–13px` |
| 核心指标 | `28–36px` |

日志、地址、端口等技术内容使用等宽字体。

### 6.3 间距和圆角

- 基础间距采用 `4px` 或 `8px` 网格。
- 常用间距：`8 / 12 / 16 / 24 / 32px`。
- 普通卡片内边距：`20–24px`。
- 控件高度：`36–40px`。
- 最小交互区域：约 `40 × 40px`。
- 卡片圆角：`10–12px`。
- 小型标签圆角：`6–8px`。

减少阴影，主要通过页面背景、白色容器和细边框建立层级。

### 6.4 图标

- 全局使用同一套线性图标库。
- 相同功能必须使用相同图标。
- 避免使用 emoji 作为功能图标。
- 危险、警告和成功状态除颜色外，还需配合图标或文字。

## 7. 无障碍与易用性要求

从截图可见的风险包括：

- 部分灰色辅助文字对比度偏低。
- 多处辅助信息字号较小。
- 当前节点和当前订阅较依赖浅色背景或边框表达。
- 开关缺少明确的开、关文本状态。
- “测试”“删除”等文字按钮点击区域可能不足。
- 表格在较窄窗口下可能出现截断或横向溢出。

改版时至少应满足：

1. 所有操作均可通过键盘完成。
2. 焦点状态清晰可见。
3. 对话框打开后正确锁定焦点，关闭后将焦点返回触发控件。
4. 不依赖颜色单独表达状态。
5. 错误信息说明原因并提供恢复方式。
6. 实时流量和连接数量更新不应高频打扰屏幕阅读器。
7. 在 Windows `125%–200%` 缩放下保持可用。
8. 窗口缩小时，表格和控制条应合理换行、折叠或滚动。

## 8. 实施优先级

### P0：结构性改版

1. 建立全局状态控制条。
2. 去除各页面重复的内核状态和停止按钮。
3. 重构侧栏，减少卡片感并保证核心状态可见。
4. 统一页面标题区高度和内容宽度。
5. 重构设置页的信息架构和保存机制。

### P1：核心功能页效率

1. 重做概览页的信息层级和流量图。
2. 增强节点搜索、筛选、测速和选择状态。
3. 调整连接表格字段，并增加暂停刷新和详情功能。
4. 补齐日志页的自动滚动、复制、清空和导出。
5. 将订阅导入改为对话框或抽屉。

### P2：视觉和交互一致性

1. 统一字体、字号、颜色、间距和圆角。
2. 替换 emoji，统一图标库。
3. 建立加载、空数据、错误和离线状态。
4. 完善悬浮、按下、禁用和键盘焦点状态。
5. 检查高分屏、窗口缩放和窄窗口布局。

## 9. 验收标准

改版完成后应验证：

- 用户在任意页面都能在 3 秒内确认当前连接状态。
- 高频的节点切换、代理开关和 TUN 开关不需要跨页面完成。
- 普通页面首屏不再重复展示内核说明和停止按钮。
- 设置项具有稳定、从上到下的阅读顺序。
- 节点、连接和日志在大量数据下仍可高效搜索和筛选。
- 所有危险操作都有清晰后果说明和确认机制。
- 所有状态同时使用文字或图标表达，不只依赖颜色。
- 在常见窗口尺寸及 Windows 缩放比例下不出现控件遮挡或不可访问区域。
